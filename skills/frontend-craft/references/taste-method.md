Source audit: official [Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill/tree/12af471f627f866411b4bd785b19646d3672784c), pinned commit `12af471f627f866411b4bd785b19646d3672784c`, v2.1.5. The expert read the complete main skill, draw/assets/inspector source, license and relevant copy/layout/imagery/critique/research guides; selected library JSON was inspected as data. No downloaded script or browser inspector was run.

## The useful mechanism is substance and selection

1. **Inventory this subject:** actual artifacts, materials, output, constraints, place or rituals, not only a category adjective. If details are proposed for a fictional brief, label them; never invent proof.
2. **Claims determine sections:** claim → concrete proof/content → visitor consequence. A section exists because it answers a question or supports a decision, not because a landing-page template has that slot.
3. **Compare organizing ideas:** same content, different dominant evidence, scale, information order and useful interaction. Check the closest competitor: an unchanged concept probably belongs to the category rather than this product.
4. **Give substance real form:** actual product media, a carefully authored artifact, useful content and an interaction that demonstrates a meaningful consequence. Carry the idea past the hero; do not end with generic filler blocks.
5. **Look and correct:** inspect real desktop/narrow renders and the main interaction, identify the largest visible problems, fix and recheck. A measured rule pass is not an aesthetic pass.

These mechanisms complement Noel and are implemented through [composition/personality](composition-and-personality.md), [component comparison](component-sourcing.md), [asset production](free-assets.md) and the primary workflow. They are not another visual skin.

## The engine also contains templates and randomness

The inspected library has 20 directions, 58 heroes, 185 section blueprints, 202 site records, 44 type systems and 56 palettes. `draw.mjs` deals three random directions from a sector/resource-compatible pool, then asks the builder to choose using the subject evidence. It can avoid recently used IDs and prefers different neighboring section shapes. These are proposal-generation aids, not original reasoning by themselves.

Sector defaults also contain conventional role sequences, and shape fallback can repeat. Therefore copying the generator wholesale would not guarantee structural variety. Do not replace the first generic model guess with the first random library option. Use the content/evidence argument and actual render to choose or reject candidates. Keep house-style bans and image/motion quotas diagnostic rather than universal rules.

The source's own evaluation uses model judges and has stated limitations; no independent outcome improvement is established here. Its useful warning is that removing ornaments without adding substance produces an empty, underbuilt page.

## Resources and execution are distinct

The local wrapper-style `taste-skill` folders inspected in this work contain only a short main file, not this version's full scripts/data/references/assets. A UI Skills text retrieval is not an installation of that engine. No upstream library or script was silently vendored or installed by this source review.

The repository is MIT; retain its notice for substantial copying. Reviewed scripts have meaningful side effects: drawing can write a direction and user-level history; the inspector can remove previous screenshots in its output, start a server and launch Chromium. Do not run them blindly or in HOME. In Nico's environment browser work remains Playwright MCP only. If the actual upstream engine is later requested, inspect the exact version, resources, licensing, output/history locations and host authorization first.

### Image-first studies: useful extraction, bounded generation

The complete locally installed `image-to-code/SKILL.md` was read (SHA-256 `4c060a8064a8b13380bc2ef3d6e6a1d0b1e316aa093cd9807d0ce9e4eeb037fa`). The [requested UI Skills entry](https://www.ui-skills.com/skills/leonxlnx/image-to-code-skill) exposed only its description; equivalence/version of the local body could not be verified. Treat it as a local interpretation, not a proven current upstream copy.

Transfer: when image-led exploration fits, make a readable visual study, inspect focal hierarchy, type relationships, spacing, component anatomy and media framing, then compare the coded render against the selected study to prevent implementation drift. Distinguish a supplied approved reference from a model-generated proposal. An image does not specify keyboard behavior, responsive rules, focus, errors or motion; derive and test those in working code.

Do **not** transfer its fixed 4/8/12-section packs, exactly-four-components/two-motion-cues prescription, numeric art-direction knobs, compulsory generation per section or unlimited regeneration. Those can reproduce the very skeleton and consumption problem being rejected. A faithful crop/zoom is valid inspection; a new generation can invent different geometry and is not evidence of hidden detail. Generate another study only to answer a concrete unresolved design question within authorized quota; stop after a failed focused attempt to reassess the strategy. No generation follows merely from reading the source.

Keep supplied/verified content authoritative. Generated testimonial names, prices, statistics, logos, product details and claims are not facts to extract into a real site. Never rasterize essential text or controls to fake fidelity. Apply the [professional review loop](professional-review-loop.md) to the actual implementation, not only to an attractive mockup.

### Vercel: implementation floor, not art direction

The [web-design-guidelines router](https://github.com/vercel-labs/agent-skills/blob/1a2c79d4e6c4a2283dc2c614b6538cbe1ed5ca62/skills/web-design-guidelines/SKILL.md) and [canonical command](https://github.com/vercel-labs/web-interface-guidelines/blob/434b7f91364665f2f733b310ec54809bf8f37937/command.md) were read completely. Use applicable checks for semantic controls, focus visibility/restoration, labels and errors, pending actions, reduced motion, stable image dimensions, touch/overflow, navigation and locale/hydration. Verify findings in the real code and browser; report actionable file/state evidence. This practical checklist is not a normative standard, complete accessibility audit, visual identity or substitute for Noel's method.

### DESIGN.md collections: relationships, not borrowed identities

The [awesome-design-md README](https://github.com/VoltAgent/awesome-design-md/tree/fcc70284932276d085f01ef9f83edde90b1258cb) and three complete contrasting examples—Claude, Nike and Dell 1996—were inspected, not all 84 advertised designs. Compare how type, image scale, density, contrast and framing support each product/era; do not import a whole brand specification as the new project's approved design system. Historical fixed-width or desktop-only choices require present-day responsive/accessibility decisions, not literal reproduction by default.

Repository MIT licensing does not license referenced trademarks, proprietary fonts, photos or product assets. Record the transferred relationship and choose assets/fonts with actual usable rights. A polished DESIGN.md still needs implemented components, states and inspected renders.
