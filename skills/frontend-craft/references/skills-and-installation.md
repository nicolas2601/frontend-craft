# Skill router and verified bootstrap recipes

Use this when choosing guidance or when an optional skill/tool is absent. Sources and commands were checked on **2026-10-29**. Preserve the current project, obtain any authorization required by the host, and never treat a remote skill as permission to install, spend or publish.

The [Product craft foundation](product-craft-foundation.md) leads design judgment. This catalog supplies optional specialists, not competing product authorities. The playbook's private `frontend-craft-suite` and `/fe-*` commands are described sources, not tools supplied or installed by this package.

## 1. Choose by job, not popularity

Use one primary visual director for a surface. Load at most two relevant specialists alongside it; replace stage context instead of stacking every skill.

| Need | Candidate | How to use it | Limit |
| --- | --- | --- | --- |
| Distinct new visual direction | Taste, upstream ID `design-taste-frontend` | Translate the brief into intentional type/composition/identity | Not a reason to replace an existing design system or require the same font bans everywhere |
| Product/style/type/palette discovery | `ui-ux-pro-max` | Search its actual local data/tools and validate recommendations against the brief | A catalog is not original art direction, user research or measured accessibility |
| Coordinating design, motion, media and copy | Official MiniMax `frontend-dev` | Learn its capability separation and asset-production briefs where appropriate | Its paid/key-based media scripts are not a free provider or installed tools here |
| Refinement, critique and coherent task workflow | Impeccable | Choose the relevant mode/command and preserve incumbent identity for refinement | Its recommendations still need actual render/behavior checks |
| Interaction craft and purposeful motion | Emil design engineering; Apple design; animate | Use response, continuity, interruption and feedback principles | Do not transplant arbitrary physics values or require Apple glass |
| Small spacing/type/hierarchy cleanup | `ibelick/baseline-ui` | Scoped checklist, after checking project defaults | Its no-gradient/custom-curve defaults conflict with some deliberate identities |
| Names, keyboard, focus, forms | `ibelick/fixing-accessibility` | Targeted review with standards verification | Not full automated WCAG conformance |
| Mobile/browser mechanics | Emil mobile-native | Viewport, touch, safe area, keyboard and real-device limits | Do not apply every global CSS recipe indiscriminately |
| A demonstrated animation bottleneck | animation-performance / fixing-motion-performance | Profile the actual interaction before changing it | Not an aesthetic director or proof that transform means GPU |
| Implementing a coherent component/token system | `dylantarre/design-system-skills` | Select the relevant token, layout or compound-component guide after choosing direction | Not an art director; examples need verification, and a small page does not require a full component library |
| React/Next implementation performance | Vercel React best practices | Use only for the relevant framework and observed problem | Not a branding or general visual-quality skill |
| Cinematic scroll narrative | `oso95/scroll-world` | Separate storytelling experience with appropriate media/budget | Prerendered video pipeline; optional external generation can cost money |
| Word/line scroll reveals and cinematic camera effects | The applicable scroll/cinematic source plus [concrete effect contracts](composition-and-personality.md) | Distinguish typographic emphasis, media scrubbing and true scene manipulation; derive the shot/state plan from the subject | Effect names do not authorize paid Higgsfield calls or guarantee exact camera/final-frame control |

`frontend-design`, UI UX Pro Max, Taste and Impeccable are alternatives for a primary design job, not four independent authorities simultaneously rewriting the same screen. Specific project instructions win over generic aesthetic defaults.

### Emil Kowalski family: route one job, do not load the family

**Runtime integration:** the existing foundation already uses Emil's useful craft spine (purpose/frequency, direct response, continuity, interruptibility, reduced motion, responsive touch behavior, measured performance and honest verification). Keep the current nuanced rules authoritative: frequency is a clue, not a hard action-count cutoff; keyboard-triggered commands still need immediate focus/selection feedback; input must not be blocked; and animation duration depends on the actual transition and context. Choose only the one guide matching the current gap. These specialist guides are not independent user studies and do not justify new rules simply because they sound strict.

**Taste v2 transfer, bounded:** keep its subject-specific inventory, section-by-section claim→evidence mapping, closest-competitor substitution test, useful real content and rendered before/after inspection. They reinforce [composition and personality](composition-and-personality.md) and [product craft foundation](product-craft-foundation.md); they do not require random direction scripts, a fixed number of images/motions, removal of all ornament, or the author's gallery-score thresholds. The fetched Taste guide describes companion assets/scripts and author-reported study findings; this review did not inspect or run those payloads or reproduce the study.

## 2. What developer recommendations actually support

There is no independently established universal “best frontend skill.” Distinguish these signals:

- [Irvin Zhan, Subframe, Oct 24, 2026](https://www.subframe.com/tips/best-claude-code-skills-for-ui-design): reports trying four skills on **one existing landing page**. Impeccable reportedly changed its look; Taste, better-ui and Emil mostly added polish. Anthropic frontend-design was discussed but not tested; UI UX Pro Max was not tested. This is a limited anecdote with no full reproducible benchmark, and the author promotes Subframe's own product/MCP.
- [Nick Babich, public LinkedIn post](https://www.linkedin.com/posts/nbabich_web-design-ui-activity-7506357263608078336-6-Ri): search-index material gives a different positioning of frontend-design, UI UX Pro Max and Taste. The exact publication date/test method was not independently verified; treat it as a weak practitioner signal, not a measured comparison.
- [Kipt shortlist](https://kipt.me/guides/best-design-skills): calls itself a shortlist, not a ranking, and includes product promotion. Useful for discovery, not independent validation.

Reddit access failed in the research path; no consensus was inferred from inaccessible discussions. Stars, catalog size and a maintainer's own examples help discovery but do not establish quality. Test the selected skill on your task with the same brief, assets, tools and acceptance checks.

## 3. Verified installation commands

### First: discover, do not guess

Run from the **intended project root**, not HOME. These commands list public upstream skills without installing them:

```bash
npx skills@1.7.4 add Leonxlnx/taste-skill --list
npx skills@1.7.4 add nextlevelbuilder/ui-ux-pro-max-skill --list
npx skills@1.7.4 add oso95/scroll-world --list
```

All three discovery commands were actually run successfully through the same pinned CLI using `npm exec --package=skills@1.7.4 -- skills ...`: Taste returned `design-taste-frontend`, UI UX Pro Max returned seven skills including `ui-ux-pro-max`, and scroll-world returned `scroll-world`. No optional skill installation was performed by those list operations.

CLI 1.7.4 `--help` was also executed. **`--list` and `--json` cannot be combined** in this version; the attempted combination failed and was corrected by removing `--json`.

### Selective project installation: Claude Code examples

Inspect upstream instructions/resources/license first. When installation is authorized:

```bash
npx skills@1.7.4 add Leonxlnx/taste-skill --skill design-taste-frontend --agent claude-code
npx skills@1.7.4 add nextlevelbuilder/ui-ux-pro-max-skill --skill ui-ux-pro-max --agent claude-code
npx skills@1.7.4 add oso95/scroll-world --skill scroll-world --agent claude-code
```

These install recipes use verified CLI flags and discovered IDs. **Installation itself was not executed during this investigation.** Installing scroll-world's instructions does not authorize running its paid generation pipeline.

The upstream scroll-world README also documents a Codex target:

```bash
npx skills@1.7.4 add oso95/scroll-world --skill scroll-world --agent codex
```

For another client, use its supported agent ID from the current CLI documentation or its documented local skill directory. Do not invent an agent ID. The optional `--global` flag changes from project to user scope; `--copy` uses copying instead of symlinks. Choose those scopes deliberately, not automatically.

Avoid `--all`: CLI help defines it as all skills, all agents **and automatic confirmation**. Do not add `-y/--yes` to skill installation by default. However, **omitting `--yes` is not a guarantee of an interactive pause**: the actual listing output detected this agent harness and announced noninteractive mode. Review destination/overwrite behavior before executing an install; preserve user control through the host's actual permission boundary.

### UI UX Pro Max: complete resources, not only its text

Its upstream README documents a dedicated CLI. Metadata checked in this investigation identified version **2.15.0**, binary `uipro`:

```bash
npm install -g ui-ux-pro-max-cli@2.15.0
uipro init --ai claude
```

This is the upstream documented approach with a pinned observed package version. It installs a **global CLI** and then project files; present the side effects and follow the host's authorization policy. It was not executed here. No undocumented `--yes` or combined `--global --ai` behavior is assumed.

After any installation, inspect the resolved skill directory and verify the resources it names actually exist. For example, if its current instructions require `scripts/search.py`, check that file before claiming the searchable database works. Review downloaded code before executing it. If payload/resources are incomplete, use the official installation path or the bundled design workflow; do not fabricate search output.

## 4. Scroll-world: purpose, dependencies and costs

[oso95/scroll-world](https://github.com/oso95/scroll-world) contains a real `skills/scroll-world/SKILL.md` plus a Claude plugin package. Its documented effect synchronizes scroll with **prerendered video clips and transitions**, not a live interactive 3D simulation.

The inspected upstream instructions use Monid as a default paid generation backend and Higgsfield as another account/credit-based path, alongside ffmpeg/ffprobe, Python and Pillow. A dedicated portrait/mobile media chain can substantially add generation and asset cost. Do not copy a fixed price estimate into future tasks; pricing and model availability change.

Free-first posture:

1. Read the desired interaction as a reference without running generation.
2. Prefer an original static/limited-motion design or already owned, licensed media when it serves the task.
3. If existing footage can be integrated with the runtime, inspect that path and its technical requirements before promising compatibility.
4. If new external generation is necessary, name the provider, uploaded material, estimated cost and mobile variants; obtain explicit approval first. No new account, balance top-up or login bypass.
5. Keep content reachable with normal scroll/keyboard and provide a reduced/static-motion path. Validate seek/decode behavior and loading on the actual target phone; a desktop film cropped to portrait is not automatically a complete mobile version.

This investigation did **not** validate a complete zero-cost scroll-world runtime integration or execute its helper scripts/media pipeline. An adapted free alternative is not the same claim as an officially supported free backend.

The repository metadata/license files for Taste, UI UX Pro Max and scroll-world declare MIT. That does not grant rights to generated/depicted brands, input images, third-party footage or every external model/service's output. Licenses were checked at source level, not legally audited.

## 5. Missing tools and MCP adapters

| Available capability | Action | Missing fallback |
| --- | --- | --- |
| Host skill loader | List/invoke the actual exposed ID with that tool's schema | Read local SKILL.md and its relative references |
| UI Skills MCP | `list_skills` on a narrow topic, then `get_skill` for a chosen returned path | Fetch verified upstream guidance or use this package's self-contained core |
| design-screenshots MCP | Metadata first; one relevant image only when needed; check dates | Public/live reference or incumbent render, with limits stated |
| shadcn MCP | Query the actual project's registry, inspect one candidate and reuse only if needed | Existing project/native components; no forced migration |
| Browser + image support | Inspect semantics and screenshots, then exercise the task | Separate nonvisual checks from an unverified visual result |
| Shell | Run actual project checks; inspect install destinations/resources | Return exact commands/patches and mark them unrun |

Useful UI Skills paths actually retrieved during this research: `ibelick/baseline-ui`, `ibelick/fixing-accessibility`, `emilkowalski/apple-design`, `emilkowalski/mobile-native`. The registry also returned the Emil animation/performance family and Impeccable metadata. A registry entry is not a skill already loaded by the current agent.

Shadcn/React Bits are optional implementation resources, not an art director. Never initialize `components.json` in HOME or another project to make a tool stop complaining. Preserve existing registries; inspect component source, dependencies and licensing before adoption. This investigation did not add or install components.

Do not copy a host-specific JSON config over someone's existing MCP settings. Confirm the actual client/version and merge a separately authorized setup change. A model cannot conjure MCP servers from a prose instruction.

## 6. Local pitfalls and conflicts

Observed on Nico's machine during this investigation:

- `find-skills` was not exposed as a callable skill in the active session; the invocation returned Unknown skill. The `skills` CLI is a discovery fallback, not proof that the missing skill ran.
- The local `taste-skill` is a wrapper/summary. Upstream discovery returned `design-taste-frontend`. Do not infer installed variants or `minimax-*` tools from a paragraph mentioning them.
- The wrapper's pseudocode `Skill("taste-skill", {variance: ...})` is **not** the schema of this session's Skill tool. Use the actual loader API/displayed names, or express the options in ordinary task text.
- UI UX Pro Max's local text loaded, but its resolved directory `/home/nicolas/.agents/skills/ui-ux-pro-max` had **no `scripts/` or `search.py`**. No database search was executed or fabricated.
- UI UX Pro Max's generic html-tailwind/default palettes and baseline-ui's no-custom-curves/no-gradients rules do not override an existing deliberate DESIGN.md. Conversely, a brand record cannot waive real accessibility requirements.
- Apple interpretation advises some effects that performance guidance discourages. Use static/limited material effects by default, and profile before adding expensive animation. Do not combine contradictory advice silently.

## 7. Installing this package elsewhere

This package requires no optional skill to run its core workflow. Copy its complete `frontend-craft/` folder, not just SKILL.md, to the receiving client's documented skill directory.

For a project whose client supports `.agents/skills`, from that project root, replace the source path below with the actual unpacked folder:

```bash
mkdir -p .agents/skills
test ! -e .agents/skills/frontend-craft && cp -R /absolute/path/to/frontend-craft .agents/skills/frontend-craft
```

The guard avoids overwriting an existing same-named skill. Stop and inspect a collision; do not force it. For OpenCode, global compatibility includes `~/.agents/skills` and `~/.claude/skills`; Claude/client discovery differs by version, so verify it rather than assuming.

Then reload discovery if required, confirm `frontend-craft` appears and invoke it through that client's displayed command/tool. If no skill loader exists, explicitly read its SKILL.md with the agent's file tools and follow its staged links. Installation, discovery, invocation and successful completion remain different facts.
