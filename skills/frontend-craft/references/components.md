# Components: take good parts, then make them belong

A library supplies implementation, never the page's identity. Pick by job (what the person selects, compares, reads, explores), add the smallest piece that does it, restyle it with the tokens, and verify it in the page. Name every library piece under `# Components` in `.craft/concept.md` with where it sits and its source.

## Search before you build (every part)

Before you hand-build a part (the nav, a gallery, a booking or order form, a menu or price list, a map, an FAQ, the footer), look it up by its job. One command asks 21st.dev (its CLI: thousands of community components with previews), cult-ui (its shadcn registry) and React Bits (the curated catalogue below):

```sh
node <skill>/scripts/components.mjs search "booking calendar with check-in and check-out" --section visit
node <skill>/scripts/components.mjs pick 21st:25156 --section visit --why "dates for the stay, nights counted"
node <skill>/scripts/components.mjs show
```

- Write the job as what the part does for the visitor, in 3-8 words; search again with other words when nothing is close.
- Open the page or preview of the two or three best before you choose; decoration (glow, shader, gradient, cursor toys) is marked and listed last.
- `pick` saves the source to `.craft/parts/<source>-<id>.json` (untrusted code: read it, never run it) and logs the choice. A 21st.dev pick spends one of the daily free retrievals (`21st usage --json`); with none left it logs the choice and you rebuild from the page.
- In a React + shadcn project, install with the piece's command inside the project; otherwise port `files[].content` to the page or the kit and keep a credit comment.
- Every search is logged in `.craft/components.json`; the check fails (`parts-unsearched`) until three parts were searched, and warns (`parts-none-taken`) when none was taken. A part nothing fits is built on the kit, with the reason under `# Components`.

## The dealt component (React Bits)

`start.mjs` deals one component from `library/components.json` (43 curated React Bits pieces that fit the direction; generated by `scripts/sync-components.mjs` from the registry). The brief prints its install lines.

| Project | How |
|---|---|
| React + Tailwind | `npx shadcn@latest add https://reactbits.dev/r/<Name>-TS-TW` inside the project (it writes `components/<Name>`) |
| React + plain CSS | the `-TS-CSS` (or `-JS-CSS`) URL with the same command |
| Vue, Svelte, Astro, plain HTML | fetch the registry JSON (`curl -s https://reactbits.dev/r/<Name>-JS-CSS`), read `files[].content`, port the effect to your framework or to the kit (`data-scrub`, `--p`), keep a credit comment |

Then: replace its demo colours and fonts with `var(--c-*)` and `var(--f-*)`; feed it the subject's real words and photographs; check it at 390 px, under reduced motion (stop or shorten its motion) and with the keyboard; keep its dependencies (gsap, motion, matter-js) to what it needs. Licence: MIT + Commons Clause, free inside a site or app, not for resale as a component kit.

If the dealt piece truly does not fit the page, use another one from the same direction (`node <skill>/scripts/start.mjs --list` shows them; `--pin component=<Name>` re-deals with it) and say why under `# Components`.

Do not add, even if they are in the catalogue: decorative WebGL backgrounds (Aurora, Particles, Galaxy, Hyperspeed, Orb, Silk, Iridescence, LiquidChrome, Threads, Plasma, Beams, Lightning, DarkVeil, Ballpit), cursor toys (SplashCursor, BlobCursor, GhostCursor, TargetCursor, ClickSpark) and gradient or shiny text. They are the look the check calls AI-made.

## Product controls

| Need | Source |
|---|---|
| Accessible menus, dialogs, selects, tabs, popovers in React | HeroUI v3 when its stack fits (React 19, Tailwind v4, React Aria); otherwise base-ui or shadcn/ui |
| Toasts, drawers, command palette, OTP | Sonner, Vaul, cmdk, input-otp |
| Numbers that roll | React Bits Counter, or NumberFlow |
| Charts | recharts; Liveline for live streams |

HeroUI CLI, read-only: `heroui info <component> --json` (API), `heroui doc <component>` (full page), `heroui list --packagePath ./package.json`. `install`, `upgrade`, `uninstall`, `agents-md` and `design-md` change the project: only inside the target project, after reading what they do.

shadcn: in a project with `components.json`, `npx shadcn@latest add <item>`; the shadcn MCP (when present) searches registries and shows examples before you add.

## Cult UI (shadcn registry, MIT)

For a React + Tailwind project with shadcn (`components.json`), Cult UI adds finished interaction pieces with one command: `npx shadcn@latest add https://cult-ui.com/r/<name>.json`. Most need `motion`. Look at the piece on cult-ui.com first, read the file it writes (untrusted code), then restyle it with the dealt tokens like any other library piece. Licence: MIT; keep the credit comment at the top of the file.

| Job | Pieces worth a look |
|---|---|
| A drawer, panel or menu that opens from its trigger | `family-drawer`, `side-panel`, `floating-panel`, `toolbar-expandable` |
| Tabs, a step form, a short form in place | `direction-aware-tabs`, `popover-form`, `wizard-expandable` |
| A card that expands into its detail | `expandable`, `expandable-screen` |
| The client's own product, framed | `mock-browser-window`, `mac-screen` (with the real screenshot) |
| A video preview that plays on hover or focus | `hover-video-player` (the client's own clip) |
| Numbers that change, a timer | `rolling-number`, `animated-number`, `timer` |
| Real proof the client gave you | `logo-carousel` (real client logos), `tweet-grid` (real posts) |
| Reorder, vote, poll inside an app | `sortable-list`, `choice-poll`, `feature-voting` |

Do not add: `gradient-heading`, `border-beam-*`, `cosmic-button`, `bg-animated-gradient`, `bg-animated-fractal-dot-grid`, `canvas-fractal-grid`, `hero-liquid-metal`, `ai-blob-warp`, `merging-bubbles`, `shader-lens-blur`, `distorted-glass`, `metal-button` and the `halo-*` set on a page that is not a tech product: they are glow, gradient and shader decoration, the look the check calls AI-made. Device mock-ups (`apple-*`) are another company's hardware: use them only for a product that runs on it.

## 21st.dev (finished community components)

`components.mjs` calls its CLI for you (`npm install -g @21st-dev/cli`, then `21st login` once; `setup.mjs --install` does the first). Search and preview are free; source retrieval is limited per day. Never generate with it (`21st generate`, `iterate`, `take`, the Magic MCP builder): that spends credits and returns the generic look. By hand:

```sh
21st search "<job>" --type c --free --limit 5 --json   # candidates with previewUrl and the page url
21st usage --json                                       # retrievals left; 401 = logged out: preview only
21st get <id> --json                                    # source of one finalist (counts against the allowance)
```

Its `installCommand` reads `$API_KEY_21ST` from the environment: run it only inside the target project, never paste or print the key.

## When a source is missing

No CLI, no login, no allowance, unclear licence: say so in the report, use an installed primitive or build the piece on the kit. Never print API keys, never log in or pay without the user asking.
